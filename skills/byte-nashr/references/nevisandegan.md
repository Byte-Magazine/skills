# تشخیص و ثبت نویسنده

منبع: `byte-new-website/content/data/authors.ts` (آرایهٔ `AUTHORS`) و
`byte-new-website/content/data/staff.ts` (عضویت تحریریه).

## فیلدهای هر نویسنده (`AuthorRecord`)

```ts
{
  id: string,           // شناسهٔ یکتا؛ الزامی
  name: string,          // نام کامل فارسی؛ الزامی
  title?: string,        // مثلاً «کارشناسی ۱۴۰۳»
  image?: string,        // مسیر عکس، معمولاً «/img/authors/<file>»
  bio?: string,           // اختیاری
  socials: {              // پیش‌فرض شیء خالی؛ همهٔ فیلدها اختیاری‌اند
    github?, linkedin?, x?, website?, email?, telegram?
  }
}
```

## روند تشخیص نویسنده — همیشه با تأیید کاربر

این اسکیل **هرگز خودش تصمیم نمی‌گیرد** کدام رکورد نویسنده درست است، حتی
اگر مطمئن به نظر برسد:

1. نام نویسندهٔ داده‌شده توسط کاربر را در `content/data/authors.ts`
   جست‌وجو کن (مطابقت دقیق یا نزدیک به نام).
2. **همیشه** نتیجه را به کاربر نشان بده و تأیید بگیر:
   - اگر یک یا چند مورد مشابه پیدا شد: به کاربر نشان بده («این نویسنده‌ها
     رو پیدا کردم؛ کدام‌یک منظور شماست؟ یا نویسندهٔ جدید است؟»).
   - اگر هیچ موردی پیدا نشد: به کاربر بگو نویسنده‌ای با این نام در
     دیتابیس نیست و بپرس آیا باید رکورد جدید ساخته شود.
3. فقط بعد از تأیید صریح کاربر، `authorId` نهایی را در frontmatter
   مقاله (`authors: [...]`) بنویس.

## ساخت رکورد نویسندهٔ جدید

اگر کاربر تأیید کرد نویسنده جدید است:

1. بپرس: نام کامل فارسی، عنوان/مقطع تحصیلی (اختیاری)، لینک‌های اجتماعی
   (اختیاری)، و آیا عکس دارد.
2. `id` را بساز — دو قرارداد در دادهٔ موجود دیده می‌شود:
   - سرنام حروف بزرگ از نام (مثل `AHMZ` برای «امیرحسین محمدزاده»)
   - نام کامل به‌صورت camelCase لاتین (مثل `aidaJabbari`)
   هرکدام که به نام نویسندهٔ جدید نزدیک‌تر/طبیعی‌تر است را انتخاب کن؛
   در صورت تردید، گزینه‌های پیشنهادی را به کاربر نشان بده تا خودش
   انتخاب کند. `id` باید یکتا باشد — قبل از نهایی کردن، در فایل جست‌وجو
   کن که تکراری نباشد.
3. اگر عکس دارد، طبق `references/tasavir.md` پردازشش کن و در
   `public/img/authors/` بگذار؛ مسیر را به‌صورت `/img/authors/<file>`
   در فیلد `image` بنویس.
4. رکورد جدید را به آرایهٔ `AUTHORS` در `content/data/authors.ts` اضافه
   کن (ترتیب الفبایی/موجود آرایه را حفظ کن، مشابه ورودی‌های اطراف).

## staff.ts

این اسکیل **هرگز** به `content/data/staff.ts` چیزی اضافه نمی‌کند مگر
کاربر صراحتاً بگوید فرد مذکور عضو تحریریه/کادر بایت است. حتی در آن
صورت هم، از کاربر بپرس این عضویت باید زیر کدام بخش (`مدیر مسئول و
سردبیر`، `تحریریه`، `ویراستاری ادبی` و ...) ثبت شود.
